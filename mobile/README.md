# Prediqo mobile app (Flutter)

## First-time setup (Windows)

Flutter is not yet installed on this machine. Install it, then generate the Android
platform folders (they are intentionally not committed yet — they are generated by
`flutter create`):

```powershell
cd mobile
flutter create . --project-name prediqo --org com.prediqo --platforms android
flutter pub get
flutter analyze
flutter test
```

`flutter create .` fills in missing `android/`, `test/` scaffolding and Gradle wrapper
files without overwriting the existing `lib/main.dart` (it only writes files that do not
already exist — do **not** pass `--overwrite`).

## Running against the local backend

Android emulator reaches the host at `10.0.2.2`:

```powershell
flutter run --dart-define=API_BASE_URL=http://10.0.2.2:8000
```

Physical device on the same Wi-Fi:

```powershell
flutter run --dart-define=API_BASE_URL=http://<PC_LAN_IP>:8000
```

## Structure (Phase 1)

```
lib/main.dart   App entry point, Riverpod provider scope, GoRouter, dark theme,
                health check against the FastAPI backend.
test/           Widget smoke test.
```

Phase 4 will introduce the design system, full navigation, all 13 screens and the
reusable match components. Additional packages (Firebase, Hive, fl_chart, Freezed,
secure storage, intl) are added in Phase 4 with `flutter pub add` at that point, so
their versions are resolved against the installed Flutter/Dart SDK instead of being
pinned speculatively in the foundation.
